# Codex Telegram Relay

Локальный инструмент для управления **существующими сессиями Codex** через собственного Telegram-бота. Каждой сессии соответствует отдельный топик в личке: туда приходят вопросы, запросы разрешений и завершённые ответы. Сообщение из Telegram возвращается в тот же диалог Codex.

### Возможности

- **Новый разговор из Telegram (main/dev после v0.1.19).** `/new` работает сразу: первым предлагает вопрос или исследование без проекта, затем подключённые проекты. Выбор создаёт отдельную сессию Codex и топик.

- **Управление без постоянного доступа к терминалу.** Получай сообщения ассистента, вопросы, запросы разрешений и результаты в Telegram; ответ возвращается в ту же сессию Codex.
- **Оставшиеся лимиты аккаунта (main/dev после v0.1.19).** `/limits` показывает актуальные окна использования Codex, оставшийся процент и время сброса, а также кредиты и ограничения расходов, если они доступны.
- **Архив переписки под рукой.** Сообщения, пересланные релеем в выбранном режиме, и твои ответы из Telegram сохраняются в топике. К обсуждениям и результатам удобно вернуться позже и найти нужное через поиск.
- **Несколько проектов одновременно.** Каждой сессии соответствует отдельный топик. Автоматический режим подхватывает новые подходящие сессии терминала и IDE.
- **Кнопки и свободный ответ.** Структурированные вопросы предлагают варианты, поддерживаемые запросы разрешений — кнопки действий. Можно написать свой ответ или приложить контекст.
- **Форматирование и rich messages.** Жирный и курсивный текст, ссылки, код, нативные заголовки и таблицы. Длинные таблицы делятся по строкам с повторением заголовков; широкие таблицы имеют читаемое представление с подписями.
- **Понятные запросы разрешений.** Карточка показывает причину, рабочую папку, точную команду или изменение и существенный контекст разрешений.
- **Скриншоты и документы.** Прикладывай файлы в топике проекта: Codex получит их через обычные механизмы изображений и файлов с сохранением своих разрешений.
- **Настраиваемый поток сообщений.** Все сообщения ассистента или компактный режим. Вывод команд и события инструментов и файлов не засоряют чат.
- **Локальная работа со своим ботом.** VPS, webhook и публичный порт не нужны. Сообщения принимает только от связанного владельца; настройки песочницы и разрешений Codex сохраняются.

`main` — релизная ветка; разработка и обычные PR идут в `dev`. Для установки конкретной версии используй тег, как в инструкции ниже.

## Что понадобится

- Node.js 22.13+, желательно Node 24 LTS. На Node 22 возможно предупреждение об экспериментальном SQLite.
- Авторизованный Codex CLI с командой `codex app-server proxy` и работающей обычной сессией. Отправь в ней первое сообщение: совершенно пустой диалог ещё нельзя подключить через resume.
- Отдельный бот от [@BotFather](https://t.me/BotFather) с включёнными **топиками в личных чатах**.
- Включённый компьютер и интернет. VPS, webhook и открытые порты не требуются.

Установка выполняется из исходников GitHub-релиза. Пакет в npm не опубликован.

## Установка

> **Защита аккаунта:** Бот даёт удалённое управление Codex. Получив доступ к привязанному Telegram-аккаунту, другой человек сможет действовать в пределах прав подключённых сессий и потенциально получить доступные файлы или их содержимое. Защищай аккаунт, токен бота и компьютер/сервер. Включи облачный пароль Telegram (двухэтапную аутентификацию), отдельный код-пароль приложения с автоблокировкой и блокировку устройства; проверяй активные сеансы. Облачный пароль защищает новые входы, а не уже разблокированный сеанс. Подробнее: [модель безопасности](SECURITY.md#protect-the-account-you-pair).

```sh
git clone --branch v0.1.19 https://github.com/data-will-be-here/codex-telegram-relay.git
cd codex-telegram-relay
npm ci
npm start -- doctor
npm start -- setup
npm start
```

Начиная с v0.1.19, `npm start` сразу запускает релей. Справка: `npm start -- --help`; выбор исполняемого файла: `npm start -- --codex-bin /полный/путь/к/codex`. Прежний `npm start -- start` тоже работает.

При `npm ci` проект собирается автоматически. Мастер `setup` предлагает выбрать проекты из открытых сессий, запрашивает токен бота без отображения ввода и показывает случайный код. Отправь указанную команду `/start КОД` своему боту **в личке**. Числовой Telegram ID отправителя станет единственным разрешённым владельцем.

Токен не нужно отправлять в чат с ИИ, issue или командную строку. Он сохраняется только в приватной папке настроек на компьютере.

После запуска `start` появляются топики с названием проекта и коротким ID сессии. Несколько сессий одного проекта получают разные топики. Сообщения работающей сессии передаются сразу через steering; в ожидающей сессии начинается следующий ход. Вывод инструментов и служебные события не пересылаются.

Ctrl+C останавливает мост, сохраняя работающий daemon Codex. Для удобной команды можно выполнить `npm link`, затем пользоваться `codex-telegram-relay setup` и `codex-telegram-relay start`.

По умолчанию бот пересылает все сообщения ассистента: пояснения, ход работы и итог. Вывод команд, события инструментов и файлов, а также внутренние reasoning-события не пересылаются. `/mode all` включает все сообщения ассистента, `/mode compact` — только первый ответ на сообщение из Telegram и итог. Настройка общая для всех сессий, сохраняется и применяется сразу к новым сообщениям без перезапуска. Шаблонного «сообщение принято» нет.

Потоковые превью включены по умолчанию: ответы появляются по мере генерации, а таблицы показываются в rich-формате, когда их структура уже доступна. `/stream off` отключает превью, `/stream on` включает их сразу для всех сессий. Эта настройка сохраняется отдельно от `/mode all|compact`. Полный ответ отправляется через постоянную очередь независимо от успеха превью. Обновления распределяются между топиками примерно с одним вызовом в секунду на весь чат; это целевой интервал, а не гарантия задержки. Очень длинное превью показывает последнюю часть, а итог отправляется всеми частями в рамках существующего лимита ответа — 40 000 символов UTF-16. Незаконченная разметка может менять вид по мере дописывания.

Текст поддерживает жирный и курсивный текст, ссылки и код; форматирование сохраняется при разбиении длинного ответа. Локальные ссылки на файлы и preview-адреса вроде `localhost` показываются обычным текстом. Если Telegram явно отклонил разметку, ответ отправляется без неё; уже принятые части и команды Codex не повторяются.

Ответы с заголовками или таблицами используют нативные Telegram rich messages. Длинные таблицы делятся по строкам с повторением заголовков; слишком широкие таблицы и крупные ячейки показываются полностью в виде абзацев с подписями. При явном отклонении формата используется читаемое резервное представление. Короткие ответы, вопросы и запросы разрешений остаются обычными сообщениями. Это не зависит от `/mode all|compact`.

В слишком больших форматированных блоках inline-стили могут упрощаться, чтобы сохранить весь текст в пределах лимитов Telegram. Команды с возвратом каретки или другими невидимыми управляющими символами показываются как явно подписанная JSON-строка с escape-последовательностями: такие символы не скрываются и не меняются при разборе Markdown.

Мост обнаруживает сессии, загруженные в общем daemon, а не открытые окна. В список может попасть старая сессия, которая всё ещё ждёт разрешения, даже если её окно уже закрыто.

Топики называются стабильно: `проект · ID`. Маршрутизация использует сохранённые ID сессий и топиков, независимо от видимого имени. При переносе установки сохрани каталог приватного состояния. Настройка статусов в названиях удалена.

Отключить такую сессию только от Telegram: `npm start -- sessions ignore ID`, затем перезапустить мост. Можно указать уникальное начало ID из `/sessions`. Вернуть пересылку: `npm start -- sessions unignore ID` и снова перезапустить мост. Состояние Codex, существующий топик и история сохраняются. Автоматического закрытия или удаления топиков при закрытии окна сейчас нет.

Структурированные вопросы Codex приходят карточками: пронумерованные варианты, описания и inline-кнопки. Несколько вопросов показываются по очереди; свой ответ можно просто написать сообщением в топике. Если вопрос написан только обычным текстом ответа, бот не придумывает для него кнопки. Секретные, слишком длинные вопросы и вопросы с более чем 10 вариантами остаются для ответа в Codex.

Каждая часть сообщения начинается с курсивной подписи `» название-проекта`, например `» tgmcp`, без полного пути. Подпись сохраняется и в уведомлениях проекта вне топиков. У общих уведомлений подпись `» codex-telegram-relay`.

## Обновление существующей установки

Начиная с v0.1.17: для новой сессии релей ждёт первого локального сообщения в Codex и только затем создаёт топик. В уже сохранённом топике он объясняет ожидание вместо сообщения о сбое подключения. Готовность проверяется автоматически; релей не отправляет начальный запрос и не повторяет отклонённые инструкции.

Улучшения надёжности в v0.1.17: наблюдаемые финальные ответы сначала сохраняются в SQLite и переживают заполненную активную очередь, последующие ответы и перезапуск. `/status` показывает число ожидающих финалов. До отправки или отмены они занимают приватное место на диске; длительный обрыв связи может увеличить этот остаток. После сужения списка проектов и перезапуска исключённая очередь отменяется. Служебные потоки, ignored-сессии и исключённые проекты не занимают лимит 64 пользовательских сессий; о достижении лимита приходит предупреждение. Периодический discovery работает параллельно приёму сообщений. Старые версии не обрабатывают новое состояние ожидания: перед откатом дождись доставки остатка.

Останови релей через Ctrl+C, сохранив Codex и приватную папку состояния. Установи новый тег в отдельную папку командами выше, затем запусти `doctor` и `start` под той же учётной записью ОС. Если бот уже связан, повторный `setup` не нужен: используются сохранённые токен, владелец, привязки топиков, отключённые сессии и прогресс доставки.

Одна приватная папка состояния предназначена для одного процесса релея. В v0.1.13 добавлен устойчивый прогресс отправки rich messages; старые версии его не понимают. Не откатывайся на старую версию, пока rich-сообщения ожидают доставки или их результат остаётся неопределённым.

В v0.1.14 потоковые rich-превью включены по умолчанию. После перезапуска релея `/stream off` оставляет только готовые сообщения, `/stream on` возвращает стриминг. Привязка бота и существующие топики сохраняются; сессии Codex перезапускать не нужно.

В v0.1.15 меню команд синхронизируется при запуске для владельца из вашей локальной привязки. После обновления перезапусти релей; повторный `setup` не нужен. На main/dev после v0.1.19 служебный интерфейс полностью английский; запуск также заменяет старые русские описания команд английскими. Обновление меню не меняет права доступа к релею.

## Установка через агента

При установке репозитория пользователю следуй сценарию ниже и для одной ссылки без промпта, и для промпта выше. Режим подключения выбирает пользователь: сама ссылка на репозиторий ещё не разрешает подключать все проекты.

**Сначала проговори безопасность аккаунта — до привязки бота, изменения охвата сессий или запуска релея.** Отправь краткое объяснение на языке пользователя, если это ещё не обсуждалось в текущем разговоре об установке. Скажи, что человек с доступом к привязанному Telegram сможет давать Codex инструкции и получать данные в пределах его прав, в том числе на подключённом сервере. Порекомендуй облачный пароль/двухэтапную аутентификацию, отдельный код-пароль приложения с автоблокировкой, блокировку устройства и проверку активных сеансов. Уточни, что облачный пароль защищает новые входы, а не уже авторизованный/разблокированный сеанс. Подробности — в [SECURITY.md](SECURITY.md#protect-the-account-you-pair); одной ссылки на него или сообщения setup в терминале недостаточно. Отдельное подтверждение принятия рисков не требуется. Самостоятельно не меняй настройки Telegram или native-разрешения пользователя.

1. Проверь ОС, Git, Node.js 22.13+ и существующую авторизованную установку Codex. Найди нативный исполняемый файл по инструкции для платформы. Если подходящих сессий нет, попроси открыть обычную сессию и отправить первое сообщение. Сервер, webhook и регистрация MCP не нужны.
2. Объясни два режима и спроси, какой включить, если пользователь ещё не сделал выбор:
   - **Автоматический (`all`)**: подключает все подходящие загруженные интерактивные сессии терминала/IDE, включая будущие проекты, примерно каждые пять секунд. Могут появиться и старые диалоги, которые daemon ещё держит загруженными. Отключённые сессии исключены. Подагенты не получают отдельных топиков; в v0.1.17 их поддерживаемые запросы разрешений приходят в топик подключённой корневой сессии.
   - **Выбранные проекты (`selected`)**: подключает только сессии внутри выбранных локальных папок; новый проект добавляется через `projects add PATH` с перезапуском релея. Рекомендуй автоматический, если нужны все новые проекты; ограниченный — если пользователь хочет подключить только часть.
   Дождись ответа перед привязкой бота или изменением охвата сессий. Это отдельная настройка от `/mode all|compact`, которая регулирует количество сообщений ассистента.
3. Возьми версию релиза из этого README и установи её тег в новую локальную папку командой клонирования из раздела выше. Выполни `npm ci`, затем `npm start -- doctor`. Сообщи установленную версию и коммит. В `main` находится релизная документация; `dev` предназначена для разработки и не используется для установки. Сохраняй изменения существующего checkout и приватное состояние; не переустанавливай через удаление конфигурации.
4. Помоги создать отдельного бота через @BotFather и включить топики в личных чатах. При первой установке запусти `npm start -- setup --scope all` или `npm start -- setup --scope selected` согласно ответу. Если твой терминал не поддерживает приватный интерактивный ввод, предложи пользователю выполнить команду в своём терминале. Токен вводится только в локальный скрытый запрос: не запрашивай его в чате, аргументах команд, переменных окружения или логах. Пользователь отправляет показанный `/start КОД` своему боту в личку; дождись успешной привязки.
5. Если бот уже привязан, пропусти setup. После выбора выполни `npm start -- sessions scope all` или `npm start -- sessions scope selected`; ограниченному режиму нужна хотя бы одна папка через `npm start -- projects add /полный/путь`. Сохрани токен, владельца, отключённые сессии и привязки топиков.
6. Запусти один релей в видимом терминале через `npm start` либо попроси перезапустить уже работающий. Процесс должен оставаться запущенным; отдельную службу без запроса не создавай. Проверь режим в сообщении запуска, совпадение с `/status` и появление топика подходящей сессии. Для автоматического режима предложи открыть сессию в новом проекте, отправить первое сообщение и проверить появление топика. Если реальная проверка бота ещё не выполнена, укажи это явно.

7. **Предложи помочь обновить пользовательский `AGENTS.md`.** Если установленная версия поддерживает `send-file`, объясни, что правило позволит будущим агентам присылать изображения, эскизы, макеты, скриншоты, анимации, видео и другие материалы для просмотра в топик текущей сессии. Предложи выбор: глобальная инструкция пользователя или правило только для проекта. Покажи текст с реальным путём к установленному CLI и добавь его после выбора области действия либо по уже полученному явному запросу. Сохрани существующие инструкции. Одна ссылка на репозиторий не разрешает редактировать глобальный `AGENTS.md`. Этот шаг не включает экспорт файлов: он остаётся отдельной локальной настройкой. Если релиз старый, объясни доступность функции; автоматически ставить `dev` ради неё не нужно.

Шаблон правила и пример команды находятся в [английской инструкции установки](README.md#agent-assisted-installation). Смысл правила: отправлять сам готовый файл штатным `send-file` в текущую нативную сессию; хранить генерируемые превью в игнорируемой папке внутри проекта; подтверждать доставку только по квитанции `sent`. Локальная ссылка может дополнять вложение. При неопределённом результате сохранить ID запроса и проверить статус; токен бота и прямые API-скрипты агенту не нужны.

## Команды в Telegram

На main/dev после v0.1.19 служебные меню, кнопки, уведомления и предупреждения превью апрувов написаны на английском независимо от языка Telegram. Тексты пользователя, ответы Codex, варианты его вопросов и описания native-профилей сохраняют исходный язык.

При настройке и каждом запуске релей сверяет меню команд через `setMyCommands` только для личного чата владельца: английские описания, включая прежнее русское меню для обновления существующих установок. Каждая установка использует свой ID владельца из локальной конфигурации, полученный при привязке бота. Тот же список используется в `/help`. Сбой обновления меню не останавливает пересылку; следующий запуск повторит проверку. `doctor` остаётся только диагностикой. Даже введённые вручную команды выполняются только от настроенного владельца в его личном чате — посторонний пользователь не получает доступ через меню.

Разработка идёт в `dev` и ветках с PR в `dev`. Проверенные релизы переносятся в `main` отдельным release PR; опубликованные теги остаются закреплены за своими релизными коммитами.

| Ввод | Действие |
| --- | --- |
| Текст в топике проекта | Ответ на ожидающий вопрос либо сообщение соответствующей сессии |
| `/sessions` | Привязанные сессии |
| `/new` | Новый разговор без проекта или сессия в подключённом проекте (main/dev после v0.1.19) |
| `/status` | Состояние соединения и число неподтверждённых доставок |
| `/limits` | Актуальные лимиты аккаунта и время сброса (main/dev после v0.1.19) |
| `/mode`, `/mode all`, `/mode compact` | Посмотреть или переключить режим сообщений для всех сессий без перезапуска |
| `/stream`, `/stream on`, `/stream off` | Посмотреть или переключить потоковые превью для всех сессий без перезапуска |
| `/bind ID` | Привязать уже созданный топик после потери ответа Telegram; отправить из самого топика |
| `/repair ID` | Явно повторить создание проблемного топика, если он не появился |
| `/questions` | Повторно показать ожидающие вопросы с кнопками и вводом ответа |
| `/model` | Выбрать модель, уровень рассуждений и скорость этой сессии |
| `/permissions` | Посмотреть и изменить native-разрешения этой сессии (main/dev после v0.1.19) |
| `/view`, `/view classic`, `/view widgets` | Выбрать Classic или экспериментальный Widgets для этой сессии (dev) |
| `/help` | Справка |
| Кнопки разрешения | Разрешить однократно либо отклонить конкретный запрос |

На `main`/`dev` после v0.1.19 команда `/limits` работает в личном чате связанного владельца и любом топике, даже без подключённой сессии. Каждый вызов получает свежие данные через существующее подключение Codex и отвечает там же. Лимиты относятся к текущему аккаунту Codex; ход модели не создаётся.

Показываются только возвращённые Codex группы и окна: наличие одновременно пятичасового и недельного лимитов не предполагается. Ответ содержит оставшийся процент, дату сброса с часовым поясом компьютера релея, время до сброса и время проверки. Тариф, кредиты и ограничения расходов добавляются при наличии данных. Сообщённое Codex ограничение остаётся видимым даже при положительном остатке. Неизвестные данные помечаются как недоступные; прошедшее время сброса не означает автоматического восстановления квоты. Очень большой список явно сокращается. Для обновления повтори `/limits`; фоновых уведомлений нет.

Это данные использования аккаунта Codex, а не баланс API-биллинга. При неподдерживаемом способе входа, недоступном методе или ошибке чтения бот сообщает о проблеме и продолжает работать, не показывая сырой ответ ошибки. После обновления перезапусти релей, чтобы загрузить команду и обновить меню. [Официальный контракт](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt).
Бот принимает команды только от владельца в его личном чате. Настройки sandbox, сеть и разрешения наследуются от Codex. `/model` явно меняет модель, уровень рассуждений и скорость текущей сессии; `/permissions` (main/dev после v0.1.19) позволяет явно изменить её профиль доступа или проверку апрувов. Команд входа в аккаунт и автоматического импорта чужой истории в Telegram нет.

Начиная с v0.1.18 основное меню команд упрощено. Обычный текст при ожидающем вопросе считается ответом на него. `/questions` возвращает карточки: можно нажать вариант или «Type an answer» и написать ответ. При нескольких вопросах сначала выбери ввод ответа на нужной карточке. `/bind` и `/repair` остаются в справке и для ручного ввода, но скрыты из основного меню команд.

Уведомление о сбое создания топика предлагает кнопки «Топик появился — привязать» и «Топик не появился — создать заново». После первой открой появившийся топик и отправь `/bind` без ID в течение десяти минут. Кнопка в исходном уведомлении не сообщает релею ID другого топика, поэтому этот шаг необходим. Вторая кнопка явно повторяет создание. Перед действием повторно проверяются доступность сессии и актуальность попытки; старые кнопки не создают дубликатов.

Подпись ответов с v0.1.18: `» project-name • название сессии из Codex`. Для сессии без имени используется короткий ID. Подпись сохраняется вместе с сообщением и файлом в очереди: переименование не меняет название у уже ожидающего отправки ответа. Название сессии может охватывать несколько запросов, это не автоматически вычисляемое описание каждого хода.

Отправь `/model` в топике подключённой сессии: бот получит свежий каталог Codex. Выбери модель, затем готовое сочетание настроек — например, `High` или `Extra High · Fast`. Второе нажатие сразу сохраняет выбор; кнопок «Обновить» и «Применить» нет. Модели, уровни рассуждений и дополнительные режимы скорости приходят из Codex; длинные списки разбиты на страницы. Быстрые режимы могут расходовать больше лимитов или кредитов. Настройки сохраняются для всех следующих запросов этой же сессии, включая локальные; текущий ответ завершится с прежними настройками. История и native-разрешения сохраняются. После переподключения релея открой `/model` заново: старые кнопки недействительны, неопределённая запись настроек автоматически не повторяется. [Протокол и проверки](docs/architecture.md#session-model-selection).

## Экспериментальные карточки активности (dev)

Отправь `/view` в топике подключённой сессии и выбери `Classic` или `Widgets · experimental`, либо используй `/view widgets`. По умолчанию остаётся Classic. Настройка сохраняется для этой native-сессии после перезапуска релея и применяется со следующего хода; текущий ход заканчивается в прежнем представлении. `/view classic` возвращает обычный вид для следующих ходов. Дополнительная локальная настройка, сайт или Telegram Mini App не нужны.

Для работы дольше примерно секунды появляется одна карточка: проект и задача, состояние, прошедшее время, реальные счётчики и текущий шаг структурированного плана при наличии, до трёх последних категорий действий. Ошибка команды не объявляет весь ход проваленным. Бюджет итераций, общий процент готовности и ETA не выдумываются. Сырые команды, аргументы/вывод инструментов и reasoning не пересылаются. Служебные подписи английские; названия задач и шаги плана сохраняют исходный язык.

Цвета берутся из темы пузыря сообщения Telegram, размеры — из настроек текста клиента. Карточка реагирует на смену темы и шрифта, учитывает место под время сообщения. При крупном тексте показывает меньше действий, при очень крупном — состояние и время. Используется фиксированный мини-HTML и небольшое приватное состояние, без внешних ресурсов, shared state и запросов из виджета. Итоговые ответы, файлы, вопросы и полные апрувы остаются обычными сообщениями. Карточка не подтверждает действия, не меняет разрешения и не останавливает Codex.

`/view` не меняет `/mode` и `/stream`: первая команда по-прежнему управляет подробностью постоянной переписки всей установки, вторая — живым предпросмотром текста ответов всей установки. Виджет может работать вместе с предпросмотром или без него. Обновления карточек и текстовые превью разделяют ограниченную очередь; вопросы, апрувы и финальные ответы имеют приоритет.

Нужны production Bot API 10.4 и поддержка виджетов Telegram-клиентом. В карточке есть caption и обычная кнопка `Classic mode` для возврата. При явном отказе widget API для сессии выбирается Classic; обычные ответы продолжают работать. Неопределённая первоначальная отправка автоматически не повторяется. После переподключения обновляются только известные карточки с проверенной привязкой. Завершённый ход не становится неизвестным из-за отсутствия в последних страницах истории; недоступный структурированный план скрывается до нового события Codex. Квитанции неопределённых отправок защищены от очистки: при 512 незавершённых/неопределённых записях новые карточки приостанавливаются с уведомлением. [Устройство и проверки](docs/architecture.md#activity-widgets).

Подтверждённые сбои соединения до отправки виджета повторяются через три секунды. Если результат первоначальной отправки неизвестен, автоматического повтора нет, а для следующих ходов выбирается Classic. `/view widgets` включает будущие карточки. Локально сохраняется безопасная категория ошибки; исходные сетевые ошибки и URL бота не записываются.

## Разрешения через /permissions (main/dev после v0.1.19)

Отправь `/permissions` в топике подключённой сессии: бот покажет её текущие разрешения и получит актуальный список разрешённых профилей из Codex. Дополнительная локальная настройка не нужна; требуется версия Codex с поддержкой native API профилей. Обычно доступны `Read-only`, `Workspace` и `Full Access`; пользовательские профили тоже появляются автоматически. Ограничения администратора остаются обязательными.

Обычный профиль применяется нажатием. `Full Access` сначала показывает предупреждение и требует отдельного подтверждения: команды смогут менять файлы за пределами проекта и обращаться к сети без запросов разрешения. Пользовательские профили тоже требуют подтверждения с описанием из Codex. Изменения сохраняются для следующих запросов этой же сессии, включая локальные; уже выполняющийся запрос и ожидающий апрув не меняются. Глобальная конфигурация и другие сессии сохраняются.

`Approval reviewer` отдельно выбирает, кто проверяет запросы разрешений: ты или автоматический проверяющий Codex. Автоматическая проверка предлагается только при поддержке и разрешении в Codex; она сохраняет sandbox. Смена профиля сохраняет выбранного проверяющего. При полном доступе апрувы не запрашиваются, поэтому этот экран скрыт; после выбора ограниченного профиля он снова доступен. Запрещённый native-политикой выбор Codex отклонит.

Открытие меню, переходы и отмена ничего не меняют. Кнопки действуют десять минут, только в исходном сообщении и топике; после переподключения открой команду заново. Если настройки изменились в терминале, старый выбор отменяется. Изменение с неподтверждённым результатом автоматически не повторяется: сначала проверь разрешения в Codex.

## Новые разговоры через /new (main/dev после v0.1.19)

`/new` работает из коробки, в том числе на старых установках без раздела `newSessions` в конфигурации. Релей сам подготовит папку `codex-telegram-conversations` рядом со своим служебным каталогом, отдельно от токена бота и базы. Если это место находится внутри Git-репозитория, используется `~/Codex/Conversations`. Выполнять `new enable` или вручную создавать папки не нужно.

В списке проектов — выбранные корни и уже известные подключённые проекты в рамках текущего режима обнаружения. Отключённые сессии и UUID-папки общих разговоров исключаются. Произвольный путь из Telegram указать нельзя. Существующие явно заданные настройки и намеренное `new disable` сохраняются.

При желании можно изменить папку или добавить проект локально, затем перезапустить релей:

```powershell
npm start -- new enable --project 'D:\code\my-project'
npm start -- new enable --scratch-root 'D:\Codex\Conversations'
```

Для своих настроек используй абсолютные канонические пути. Общая рабочая область должна находиться вне Git-репозиториев, папок проектов, приватных данных релея и `CODEX_HOME`. `npm start -- new` показывает действующие настройки, `new disable` отключает создание новых сессий, сохраняя работу существующих разговоров. Эти команды необязательны: после обновления достаточно загрузить новый код релея, дополнительная настройка не требуется.

`/new` работает в любом топике лички владельца, включая непривязанный, и без топика. Первым идёт **No project — question / research**, затем текущий доступный проект и остальные известные проекты. Для длинного списка есть страницы, до выбора — `Cancel`. Нажатие сразу запускает создание. Первую задачу нужно написать в новом топике; сообщения и ответы на вопросы в старом топике остаются в прежней сессии.

Каждому разговору без проекта выделяется постоянная папка `<scratchRoot>/<идентификатор операции>`. Новая сессия разделяет историю переписки, папка — созданные отчёты, скачанные файлы и скрипты. Глобальные настройки Codex, скилы, плагины, инструкции и память сохраняются. Автоудаления папок нет: разговор можно продолжить, а результаты отправить штатным `send-file`. В заголовках используется `No project`, UUID-папки не засоряют список проектов. При выборе обычного проекта файлы и текущая Git-ветка общие; отдельный worktree и копирование истории `/new` не выполняет.

Сначала релей создаёт и подтверждает Telegram-топик. Только после этого создаётся сессия Codex через штатные `thread/start` и `thread/name/set`, без искусственного сообщения модели. При ошибке или неопределённом результате запроса топика сессия Codex не создаётся. В меню доступны явный повтор, отмена или выбор существующего пустого топика с последующим `/bind`. Подтверждённый сбой соединения до отправки повторяется через три секунды; запрос с неизвестным результатом автоматически не повторяется. `/model` доступна до первого задания. Обычные новые терминальные сессии по-прежнему ожидают первое локальное сообщение. Разрешения, модель и конфигурация проекта наследуются от Codex.

Компьютер, релей и фоновый Codex должны работать. Отдельное окно терминала для каждой сессии и Windows-приложение не нужны; текущий proxy релея сам daemon не запускает. Создание выполняется отдельно от сообщений и загрузок. Двойные нажатия не создают дубликаты. Если ответ Codex потерян, релей ищет уже созданную сессию по точной метке операции; неизвестный результат не повторяется новым `thread/start`. Известный ID сохраняется при ошибках имени и топика. Для неопределённого создания Telegram-топика остаются `/bind` и `/repair`. Архивированные сессии автоматически не возобновляются и не заменяются. [Архитектура](docs/architecture.md#new-conversation-creation).

Для старых операций, которые уже успели создать сессию Codex до топика, исходное меню `/new` показывает сохранённый ID и действия восстановления. Повторный `/new` возвращает к этим действиям. Восстановление использует ту же сессию, не создавая замену. Уже сохранённые сессии остаются доступными.

Кнопки восстановления могут загрузить выгруженный разговор, созданный через `/new`, по сохранённому ID после проверки неархивированной истории и разрешённой папки. Первое сообщение в терминале не требуется. Для обычных терминальных сессий сохраняются прежние проверки готовности. `BOT_TOPIC_WRONG_HOME` считается неопределённым результатом создания: перед повтором нужно проверить Telegram, поскольку ответ с ошибкой не доказывает отсутствие видимого топика. Релей не вычисляет ID топика по названию или ID сообщения.

## Windows

Запускается непосредственно `codex.exe`, без `cmd.exe` и batch-обёрток. При необходимости укажи полный путь:

```powershell
npm start -- doctor --codex-bin 'C:\полный\путь\codex.exe'
npm start -- setup --codex-bin 'C:\полный\путь\codex.exe'
```

### Автоматическое подключение новых проектов

Автоматическое подключение включается явно:

```sh
npm start -- sessions scope all
```

Один раз перезапусти релей. После этого новые интерактивные сессии, в том числе в новых проектах, подхватываются без повторной настройки и перезапусков. Проверка выполняется примерно каждые пять секунд; в новой сессии нужно отправить первое сообщение, чтобы появилась история для подключения. Режим включает также IDE-сессии и старые интерактивные диалоги, которые daemon ещё держит загруженными. Явно отключённые сессии и временные контексты остаются исключены. Подагенты не получают отдельных топиков; в v0.1.17 их поддерживаемые запросы разрешений приходят в топик подключённой корневой сессии.

Для первой установки есть `npm start -- setup --scope all`. Обычный `setup` и прежние конфигурации сохраняют ограничение выбранными проектами. `npm start -- sessions scope` показывает сохранённый режим, `/status` — режим работающего релея. Вернуть ограничения: `npm start -- sessions scope selected`, затем перезапустить релей. Изменять эту настройку можно только локально.

### Добавление проекта в ограниченном режиме

Добавить проект в список выбранных можно локально, затем перезапустить мост:

```powershell
npm start -- projects add 'D:\code\another-project'
```

## Настройки и надёжность

На macOS/Linux поддерживаются ссылки на исполняемый Codex и поиск нативного файла за npm-лаунчером, включая вложенные и общие platform-пакеты. Скриптовые обёртки не запускаются. CI отдельно устанавливает официальный Codex 0.166.0 и проверяет нативную команду proxy на каждой ОС; полный обмен реальной сессии с Telegram на macOS/Linux ещё требует проверки.

Данные находятся вне репозитория: `%LOCALAPPDATA%\codex-telegram-relay` на Windows; `$XDG_CONFIG_HOME/codex-telegram-relay` либо `~/.config/codex-telegram-relay` на Linux/macOS. Папка содержит токен, настройки и SQLite-базу с привязками и текстами исходящих сообщений. Доступ ограничивается при настройке. Для отдельной установки можно задать `CODEX_TELEGRAM_RELAY_HOME`.

Временная недоступность одной сессии не отключает остальные. Потеря самого соединения с Codex по-прежнему вызывает переподключение. В v0.1.17 временные ошибки получения updates из Telegram повторяются с задержкой, сохраняя здоровое соединение с Codex; неверные учётные данные и конфликт двух poller-процессов останавливают релей. При запуске временные сетевые и серверные ошибки проверки бота или webhook повторяются через три секунды до восстановления Telegram; более длительный интервал rate limit соблюдается. Ctrl+C останавливает повторные попытки запуска.

В v0.1.17 повтор того же ожидающего апрувала после переподключения или перезапуска релея обновляет кнопки существующей карточки. Разные нативные запросы и изменённые команды показываются отдельно. Если подтверждение первоначальной отправки потерялось, новая копия автоматически не отправляется; такой запрос нужно обработать в Codex. У карточек старой версии нет необходимой сохранённой идентичности, поэтому первый повтор после обновления может создать одну новую карточку. [Исследование и проверки](docs/research/repeated-approval-cards-2026-11-05.md).

В исходниках новее v0.1.19 длинные поддерживаемые апрувы приходят пронумерованными сообщениями (`1/3`, `2/3`, `3/3`) со сворачиваемыми блоками, раскрывающимися по нажатию, общим номером запроса и подписью проекта/задачи. Большие встроенные скрипты и примеры кода показываются в одной компактной карточке блоком кода до шести строк вместе с пометкой о сокращении; обычные аргументы команд сохраняются полностью; длинные цитаты в пояснении тоже могут сокращаться, а повтор кода в правиле разрешений ссылается на превью команды. Несколько примеров кода делят общий бюджет; пропуск остальных отмечается явно. В компактных карточках кода используются обычное форматирование и кнопки без сворачиваемых цитат. Заметное предупреждение объясняет, что кнопка одобряет полную исходную команду, доступную в Codex. Предлагаемые изменения файлов и запрашиваемые разрешения сохраняются полностью. Кнопки решения появляются на последней части после подтверждения доставки всех частей. После перезапуска релей продолжает оставшиеся отправки, когда Codex заново подтвердит ожидающий запрос; при неизвестном результате отправки нужно проверить Codex. Это изменение появилось после v0.1.19.

Перед созданием топика мост сохраняет попытку в базе. Если Telegram мог создать топик, но ответ потерялся, автоматические повторы останавливаются даже после перезапуска. Бот присылает инструкции: если топик появился, отправить `/bind ID` из него; если не появился — явно повторить создание командой `/repair ID`. Эти команды доступны только владельцу и не запускают команду в Codex.

Сохранённая привязка топика не означает, что сессия запущена. `/sessions` показывает номер сохранённого топика и состояние подключения. В этом топике `/bind ID` или `/repair ID` повторяет поиск и подключение загруженной сессии. Если сессия выгружена, возобнови именно этот разговор локально через `codex resume ID` или открой его в IDE; мост подключится автоматически. Команда из другого топика покажет сохранённый номер без переноса привязки. Создание нового топика не загружает сессию Codex.

При явной ошибке «топик не найден» мост создаёт замену для загруженной сессии и переносит недоставленные ответы. Старая история не импортируется; прежние кнопки разрешений отключаются, а ожидающие вопросы подключаются заново. Чтобы удалить топик насовсем, сначала отключи его сессию командой `sessions ignore ID`, затем удали топик в Telegram.

После обрыва мост переподключается. Повторные Telegram updates не выполняют команду дважды. При неопределённом результате записи она **не повторяется автоматически**: сначала проверь терминал. Старые вопросы, полученные до подключения моста, иногда требуют ответа в терминале. Неподдерживаемые approvals также остаются для проверки в терминале; в опубликованной v0.1.19 это относится и к слишком большим карточкам.

Это первая версия для разработчика. На настоящем Codex CLI 0.166.0 под Windows проверены подключение, финальный ответ, вопрос, steering и отмена разрешения через второго клиента с Telegram-имитатором. Затем на настоящем боте проверены топики, двусторонние сообщения, форматирование и ответ на нативный вопрос. Сон компьютера и восстановление связи, другие версии Codex и установка на чистой машине ещё требуют проверки. Подробности: [проверки](docs/verification.md), [архитектура и ограничения](docs/architecture.md), [безопасность](SECURITY.md).

Самостоятельный проект, не официальный продукт OpenAI или Telegram. Лицензия MIT.

Начиная с v0.1.17 поддерживаемые разрешения команд, изменений файлов и доступа от загруженных подагентов приходят в топик подключённой корневой сессии. Карточка показывает имя агента и полный ID. После переподключения или восстановления топика релей отдельно подписывается на подходящих потомков, чтобы получить ожидающие запросы; решение отправляется исходному запросу подагента один раз. Доступность всей цепочки родителей проверяется повторно перед ответом. Сообщения и вопросы подагентов не зеркалируются, инструкции из Telegram по-прежнему адресованы корневой сессии. [Реализация и проверки](docs/research/subagent-approvals-2026-11-05.md).

## Вложения и вопросы

**Отправка файлов обратно доступна с v0.1.17.** После установки содержащей её версии и одного перезапуска релея включи экспорт локально: `npm start -- files enable`. После этого агент может вызвать `node /абсолютный/путь/relay/dist/src/cli.js send-file /путь/проекта/demo.mp4 --session SESSION_ID`. MP4 придёт как видео, остальные файлы — документами; `--as document` сохраняет любой файл документом. Подтверждать каждый файл отдельно не нужно. Агент установки должен объяснить риск доступа к файлам через привязанный аккаунт и уточнить включение экспорта; через команды бота его включить нельзя.

Лимит — 49 000 000 байт на файл, 16 ожидающих запросов и 200 МБ приватных снимков. Разрешены обычные файлы внутри проекта выбранной сессии. Ссылки, hard links, сетевые пути, специальные файлы, приватные данные релея и альтернативные потоки Windows отклоняются. Выбор сессии: `--session`, затем `CODEX_THREAD_ID`, затем единственная сессия текущего каталога; неоднозначность приводит к ошибке. Токен процессу отправки не нужен.

Команда ждёт до трёх минут и возвращает JSON: только `sent` с ID сообщения означает доставку. `--no-wait` сразу возвращает квитанцию, `files status REQUEST_ID` показывает результат. Одинаковый запрос не дублируется; для повторной проверки сохраняй его ID. При `uncertain` сначала проверь Telegram: автоматической повторной отправки нет. Намеренный повтор потребует нового `--request-id ID`. Загрузка работает отдельно от сообщений и кнопок. Невысланные запросы истекают через десять минут, снимки удаляются после обработки. `files disable` запрещает новые и ещё не начатые загрузки; начатую загрузку отозвать нельзя. [Подробное описание](README.md#sending-files-back-development-version).

В топик проекта можно отправить фото, скриншот, документ, голосовое, аудио, видео, видеосообщение или анимацию. Файлы скачиваются через официальный Telegram getFile; ссылка с токеном бота не передаётся Codex. Лимит облачного скачивания — 20 МиБ на файл. Приватный кеш находится вне репозитория: до 200 МиБ, хранение семь дней, очистка просроченных файлов при следующем вложении. Альбом приходит отдельными сообщениями, а не одним общим запросом.

JPEG, PNG и WebP передаются как изображения, другие файлы — с локальным путём. Для небольших UTF-8 файлов добавляется ограниченный фрагмент текста. Подпись также передаётся сессии. В ответе на нативный вопрос вложение представлено текстом и путём: для просмотра агенту могут потребоваться его обычные разрешения. Мост не запускает и не распаковывает загруженные файлы.

Звук и видео принимаются как файлы, но эта версия не расшифровывает речь и не извлекает кадры. Для этого нужен отдельный локальный обработчик либо явно разрешённый внешний сервис. Права сессии при чтении и обработке файлов не расширяются.

Вопросы request_user_input_async тоже доставляются с кнопками: Codex 0.166.0 не показывает их через App Server, поэтому мост читает соответствующие записи выбранной сессии. Журнал просматривается порциями по 1 МиБ; сохраняются только записи вопросов/ответов текущего хода, с лимитом отдельной записи 256 КиБ. Большой вывод инструментов не обрезает восстановление вопросов и не вызывает предупреждения только из-за размера журнала. Ответ отправляется в ту же сессию как обычное сообщение пользователя; исходная форма в интерфейсе Codex может остаться открытой. При первом подключении восстанавливаются вопросы последнего хода в пределах семи дней. Для известных незакрытых вопросов граница восстановления сохраняется и после новых ходов/перезапусков, без импорта посторонней старой истории. При неподдерживаемом или секретном вопросе приходит уведомление о необходимости ответа в терминале. При выключенном мосте или потере связи уведомление доставить невозможно.

## Обновление Codex и восстановление пути

Если обновление удалило сохранённый бинарник Codex, открой обычные сессии Codex и перезапусти релей. Он повторно проверит штатные места установки и сохранит новый путь только после успешного подключения и проверки списка сессий общего daemon. Токен, привязка владельца и ID топиков сохраняются. Проверка не скачивает CLI, не запускает отдельный daemon и не обращается к модели. Совместимость за пределами проверенной версии Codex требует отдельной проверки.

Если автоматический поиск не помог, укажи установленный нативный бинарник:

```sh
npm start -- --codex-bin /absolute/path/to/native/codex
```

На Windows нужен абсолютный путь к codex.exe. Существующий, но некорректный файл не заменяется молча. doctor --codex-bin PATH проверяет указанный путь без изменения конфигурации.

Известные незакрытые host-вопросы сохраняются при новом ходе и переподключении. Граница восстановления расширяется только для этих вопросов; посторонние старые вопросы не импортируются. О превышении размера или количества вопросов приходит уведомление о необходимости терминала. Частичные ответы хранятся приватно до семи дней и восстанавливаются при совпадении стабильных ID и содержания вопросов. При явном отказе Codex ответ можно повторить; принятые или неопределённые отправки автоматически не повторяются.
