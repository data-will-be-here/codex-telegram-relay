# Codex Telegram Relay

Локальный инструмент для управления **существующими сессиями Codex** через собственного Telegram-бота. Каждой сессии соответствует отдельный топик в личке: туда приходят вопросы, запросы разрешений и завершённые ответы. Сообщение из Telegram возвращается в тот же диалог Codex.

### Возможности

- **Управление без постоянного доступа к терминалу.** Получай сообщения ассистента, вопросы, запросы разрешений и результаты в Telegram; ответ возвращается в ту же сессию Codex.
- **Несколько проектов одновременно.** Каждой сессии соответствует отдельный топик. Автоматический режим подхватывает новые подходящие сессии терминала и IDE.
- **Кнопки и свободный ответ.** Структурированные вопросы предлагают варианты, поддерживаемые запросы разрешений — кнопки действий. Можно написать свой ответ или приложить контекст.
- **Форматирование и rich messages.** Жирный и курсивный текст, ссылки, код, нативные заголовки и таблицы. Длинные таблицы делятся по строкам с повторением заголовков; широкие таблицы имеют читаемое представление с подписями.
- **Понятные запросы разрешений.** Карточка показывает причину, рабочую папку, точную команду или изменение и существенный контекст разрешений.
- **Скриншоты и документы.** Прикладывай файлы в топике проекта: Codex получит их через обычные механизмы изображений и файлов с сохранением своих разрешений.
- **Настраиваемый поток сообщений.** Все сообщения ассистента или компактный режим. Вывод команд и события инструментов и файлов не засоряют чат.
- **Локальная работа со своим ботом.** VPS, webhook и публичный порт не нужны. Сообщения принимает только от связанного владельца; настройки песочницы и разрешений Codex сохраняются.

**Можно установить через своего ИИ-агента.** Отправь ему ссылку на репозиторий и этот промпт:

**Агенту установки:** раздел [«Установка через агента»](#установка-через-агента) обязателен и для одной ссылки на репозиторий, и для промпта ниже. До привязки бота или запуска релея проговори пользователю последствия для безопасности аккаунта.

```text
Установи мне Codex Telegram Relay: https://github.com/data-will-be-here/codex-telegram-relay/tree/main
Следуй разделу README «Установка через агента». До привязки бота или запуска релея объясни риски удалённого управления и порекомендуй настройки защиты Telegram и устройства из этого раздела. Объясни разницу между автоматическим подключением всех сессий и ограничением выбранными проектами, затем спроси, какой режим мне нужен. Установи инструмент локально и помоги подключить моего Telegram-бота. Токен я введу сам локально со скрытым вводом — не проси присылать его в этот чат.
```

## Что понадобится

- Node.js 22.13+, желательно Node 24 LTS. На Node 22 возможно предупреждение об экспериментальном SQLite.
- Авторизованный Codex CLI с командой `codex app-server proxy` и работающей обычной сессией. Отправь в ней первое сообщение: совершенно пустой диалог ещё нельзя подключить через resume.
- Отдельный бот от [@BotFather](https://t.me/BotFather) с включёнными **топиками в личных чатах**.
- Включённый компьютер и интернет. VPS, webhook и открытые порты не требуются.

Установка выполняется из исходников GitHub-релиза. Пакет в npm не опубликован.

## Установка

> **Защита аккаунта:** Бот даёт удалённое управление Codex. Получив доступ к привязанному Telegram-аккаунту, другой человек сможет действовать в пределах прав подключённых сессий и потенциально получить доступные файлы или их содержимое. Защищай аккаунт, токен бота и компьютер/сервер. Включи облачный пароль Telegram (двухэтапную аутентификацию), отдельный код-пароль приложения с автоблокировкой и блокировку устройства; проверяй активные сеансы. Облачный пароль защищает новые входы, а не уже разблокированный сеанс. Подробнее: [модель безопасности](SECURITY.md#protect-the-account-you-pair).

```sh
git clone --branch v0.1.15 https://github.com/data-will-be-here/codex-telegram-relay.git
cd codex-telegram-relay
npm ci
npm start -- doctor
npm start -- setup
npm start -- start
```

При `npm ci` проект собирается автоматически. Мастер `setup` предлагает выбрать проекты из открытых сессий, запрашивает токен бота без отображения ввода и показывает случайный код. Отправь указанную команду `/start КОД` своему боту **в личке**. Числовой Telegram ID отправителя станет единственным разрешённым владельцем.

Токен не нужно отправлять в чат с ИИ, issue или командную строку. Он сохраняется только в приватной папке настроек на компьютере.

После запуска `start` появляются топики с названием проекта и коротким ID сессии. Несколько сессий одного проекта получают разные топики. Сообщения работающей сессии передаются сразу через steering; в ожидающей сессии начинается следующий ход. Вывод инструментов и служебные события не пересылаются.

Ctrl+C останавливает мост, сохраняя работающий daemon Codex. Для удобной команды можно выполнить `npm link`, затем пользоваться `codex-telegram-relay setup` и `codex-telegram-relay start`.

По умолчанию бот пересылает все сообщения ассистента: пояснения, ход работы и итог. Вывод команд, события инструментов и файлов, а также внутренние reasoning-события не пересылаются. `/mode all` включает все сообщения ассистента, `/mode compact` — только первый ответ на сообщение из Telegram и итог. Настройка общая для всех сессий, сохраняется и применяется сразу к новым сообщениям без перезапуска. Шаблонного «сообщение принято» нет.

Потоковые превью включены по умолчанию: ответы появляются по мере генерации, а таблицы показываются в rich-формате, когда их структура уже доступна. `/stream off` отключает превью, `/stream on` включает их сразу для всех сессий. Эта настройка сохраняется отдельно от `/mode all|compact`. Полный ответ отправляется через постоянную очередь независимо от успеха превью. Обновления распределяются между топиками примерно с одним вызовом в секунду на весь чат; это целевой интервал, а не гарантия задержки. Очень длинное превью показывает последнюю часть, а итог отправляется всеми частями в рамках существующего лимита ответа — 40 000 символов UTF-16. Незаконченная разметка может менять вид по мере дописывания.

Текст поддерживает жирный и курсивный текст, ссылки и код; форматирование сохраняется при разбиении длинного ответа. Локальные ссылки на файлы и preview-адреса вроде `localhost` показываются обычным текстом. Если Telegram явно отклонил разметку, ответ отправляется без неё; уже принятые части и команды Codex не повторяются.

Ответы с заголовками или таблицами используют нативные Telegram rich messages. Длинные таблицы делятся по строкам с повторением заголовков; слишком широкие таблицы и крупные ячейки показываются полностью в виде абзацев с подписями. При явном отклонении формата используется читаемое резервное представление. Короткие ответы, вопросы и запросы разрешений остаются обычными сообщениями. Это не зависит от `/mode all|compact`.

В слишком больших форматированных блоках inline-стили могут упрощаться, чтобы сохранить весь текст в пределах лимитов Telegram. Команды с возвратом каретки или другими невидимыми управляющими символами показываются как явно подписанная JSON-строка с escape-последовательностями: такие символы не скрываются и не меняются при разборе Markdown.

Мост обнаруживает сессии, загруженные в общем daemon, а не открытые окна. В список может попасть старая сессия, которая всё ещё ждёт разрешения, даже если её окно уже закрыто.

Топики называются стабильно: `проект · ID`. Маршрутизация использует сохранённые ID сессий и топиков, независимо от видимого имени. При переносе установки сохрани каталог приватного состояния. Настройка статусов в названиях удалена.

Отключить такую сессию только от Telegram: `npm start -- sessions ignore ID`, затем перезапустить мост. Можно указать уникальное начало ID из `/sessions`. Вернуть пересылку: `npm start -- sessions unignore ID` и снова перезапустить мост. Состояние Codex, существующий топик и история сохраняются. Автоматического закрытия или удаления топиков при закрытии окна сейчас нет.

Структурированные вопросы Codex приходят карточками: пронумерованные варианты, описания и inline-кнопки. Несколько вопросов показываются по очереди; свой ответ можно просто написать сообщением в топике. Если вопрос написан только обычным текстом ответа, бот не придумывает для него кнопки. Секретные, слишком длинные вопросы и вопросы с более чем 10 вариантами остаются для ответа в Codex.

Каждая часть сообщения начинается с курсивной подписи `» название-проекта`, например `» tgmcp`, без полного пути. Подпись сохраняется и в уведомлениях проекта вне топиков. У общих уведомлений подпись `» codex-telegram-relay`.

## Обновление существующей установки

Останови релей через Ctrl+C, сохранив Codex и приватную папку состояния. Установи новый тег в отдельную папку командами выше, затем запусти `doctor` и `start` под той же учётной записью ОС. Если бот уже связан, повторный `setup` не нужен: используются сохранённые токен, владелец, привязки топиков, отключённые сессии и прогресс доставки.

Одна приватная папка состояния предназначена для одного процесса релея. В v0.1.13 добавлен устойчивый прогресс отправки rich messages; старые версии его не понимают. Не откатывайся на старую версию, пока rich-сообщения ожидают доставки или их результат остаётся неопределённым.

В v0.1.14 потоковые rich-превью включены по умолчанию. После перезапуска релея `/stream off` оставляет только готовые сообщения, `/stream on` возвращает стриминг. Привязка бота и существующие топики сохраняются; сессии Codex перезапускать не нужно.

В v0.1.15 меню команд синхронизируется при запуске для владельца из вашей локальной привязки. После обновления перезапусти релей; повторный `setup` не нужен. Для русского языка Telegram используются русские описания, по умолчанию — английские. Обновление меню не меняет права доступа к релею.

## Установка через агента

При установке репозитория пользователю следуй сценарию ниже и для одной ссылки без промпта, и для промпта выше. Режим подключения выбирает пользователь: сама ссылка на репозиторий ещё не разрешает подключать все проекты.

**Сначала проговори безопасность аккаунта — до привязки бота, изменения охвата сессий или запуска релея.** Отправь краткое объяснение на языке пользователя, если это ещё не обсуждалось в текущем разговоре об установке. Скажи, что человек с доступом к привязанному Telegram сможет давать Codex инструкции и получать данные в пределах его прав, в том числе на подключённом сервере. Порекомендуй облачный пароль/двухэтапную аутентификацию, отдельный код-пароль приложения с автоблокировкой, блокировку устройства и проверку активных сеансов. Уточни, что облачный пароль защищает новые входы, а не уже авторизованный/разблокированный сеанс. Подробности — в [SECURITY.md](SECURITY.md#protect-the-account-you-pair); одной ссылки на него или сообщения setup в терминале недостаточно. Отдельное подтверждение принятия рисков не требуется. Самостоятельно не меняй настройки Telegram или native-разрешения пользователя.

1. Проверь ОС, Git, Node.js 22.13+ и существующую авторизованную установку Codex. Найди нативный исполняемый файл по инструкции для платформы. Если подходящих сессий нет, попроси открыть обычную сессию и отправить первое сообщение. Сервер, webhook и регистрация MCP не нужны.
2. Объясни два режима и спроси, какой включить, если пользователь ещё не сделал выбор:
   - **Автоматический (`all`)**: подключает все подходящие загруженные интерактивные сессии терминала/IDE, включая будущие проекты, примерно каждые пять секунд. Могут появиться и старые диалоги, которые daemon ещё держит загруженными. Отключённые сессии и подагенты исключены.
   - **Выбранные проекты (`selected`)**: подключает только сессии внутри выбранных локальных папок; новый проект добавляется через `projects add PATH` с перезапуском релея. Рекомендуй автоматический, если нужны все новые проекты; ограниченный — если пользователь хочет подключить только часть.
   Дождись ответа перед привязкой бота или изменением охвата сессий. Это отдельная настройка от `/mode all|compact`, которая регулирует количество сообщений ассистента.
3. Возьми версию релиза из этого README и установи её тег в новую локальную папку командой клонирования из раздела выше. Выполни `npm ci`, затем `npm start -- doctor`. Сообщи установленную версию и коммит. В `main` находится релизная документация; `dev` предназначена для разработки и не используется для установки. Сохраняй изменения существующего checkout и приватное состояние; не переустанавливай через удаление конфигурации.
4. Помоги создать отдельного бота через @BotFather и включить топики в личных чатах. При первой установке запусти `npm start -- setup --scope all` или `npm start -- setup --scope selected` согласно ответу. Если твой терминал не поддерживает приватный интерактивный ввод, предложи пользователю выполнить команду в своём терминале. Токен вводится только в локальный скрытый запрос: не запрашивай его в чате, аргументах команд, переменных окружения или логах. Пользователь отправляет показанный `/start КОД` своему боту в личку; дождись успешной привязки.
5. Если бот уже привязан, пропусти setup. После выбора выполни `npm start -- sessions scope all` или `npm start -- sessions scope selected`; ограниченному режиму нужна хотя бы одна папка через `npm start -- projects add /полный/путь`. Сохрани токен, владельца, отключённые сессии и привязки топиков.
6. Запусти один релей в видимом терминале через `npm start -- start` либо попроси перезапустить уже работающий. Процесс должен оставаться запущенным; отдельную службу без запроса не создавай. Проверь режим в сообщении запуска, совпадение с `/status` и появление топика подходящей сессии. Для автоматического режима предложи открыть сессию в новом проекте, отправить первое сообщение и проверить появление топика. Если реальная проверка бота ещё не выполнена, укажи это явно.

## Команды в Telegram

При настройке и каждом запуске релей сверяет меню команд через `setMyCommands` только для личного чата владельца: русские описания и английские по умолчанию. Каждая установка использует свой ID владельца из локальной конфигурации, полученный при привязке бота. Тот же список используется в `/help`. Сбой обновления меню не останавливает пересылку; следующий запуск повторит проверку. `doctor` остаётся только диагностикой. Даже введённые вручную команды выполняются только от настроенного владельца в его личном чате — посторонний пользователь не получает доступ через меню.

Разработка идёт в `dev` и ветках с PR в `dev`. Проверенные релизы переносятся в `main` отдельным release PR; опубликованные теги остаются закреплены за своими релизными коммитами.

| Ввод | Действие |
| --- | --- |
| Текст в топике проекта | Ответ на ожидающий вопрос либо сообщение соответствующей сессии |
| `/say ТЕКСТ` | Инструкция Codex даже при ожидающем вопросе |
| `/sessions` | Привязанные сессии |
| `/status` | Состояние соединения и число неподтверждённых доставок |
| `/mode`, `/mode all`, `/mode compact` | Посмотреть или переключить режим сообщений для всех сессий без перезапуска |
| `/stream`, `/stream on`, `/stream off` | Посмотреть или переключить потоковые превью для всех сессий без перезапуска |
| `/bind ID` | Привязать уже созданный топик после потери ответа Telegram; отправить из самого топика |
| `/repair ID` | Явно повторить создание проблемного топика, если он не появился |
| `/questions` | Повторить текущие вопросы |
| `/help` | Справка |
| Кнопки разрешения | Разрешить однократно либо отклонить конкретный запрос |

Бот принимает команды только от владельца в его личном чате. Настройки sandbox, сеть, модель и разрешения наследуются от Codex. Команд отключения sandbox, входа в аккаунт, загрузки файлов и импорта чужой истории в Telegram нет.

## Windows

Запускается непосредственно `codex.exe`, без `cmd.exe` и batch-обёрток. При необходимости укажи полный путь:

```powershell
npm start -- doctor --codex-bin 'C:\полный\путь\codex.exe'
npm start -- setup --codex-bin 'C:\полный\путь\codex.exe'
```

### Автоматическое подключение новых проектов

```sh
npm start -- sessions scope all
```

Один раз перезапусти релей. После этого новые интерактивные сессии, в том числе в новых проектах, подхватываются без повторной настройки и перезапусков. Проверка выполняется примерно каждые пять секунд; в новой сессии нужно отправить первое сообщение, чтобы появилась история для подключения. Режим включает также IDE-сессии и старые интерактивные диалоги, которые daemon ещё держит загруженными. Явно отключённые сессии, подагенты и временные контексты остаются исключены.

Для первой установки есть `npm start -- setup --scope all`. Обычный `setup` и прежние конфигурации сохраняют ограничение выбранными проектами. `npm start -- sessions scope` показывает сохранённый режим, `/status` — режим работающего релея. Вернуть ограничения: `npm start -- sessions scope selected`, затем перезапустить релей. Изменять эту настройку можно только локально.

### Добавление проекта в ограниченном режиме

Добавить проект в список выбранных можно локально, затем перезапустить мост:

```powershell
npm start -- projects add 'D:\code\another-project'
```

## Настройки и надёжность

На macOS/Linux поддерживаются ссылки на исполняемый Codex и поиск нативного файла за npm-лаунчером, включая вложенные и общие platform-пакеты. Скриптовые обёртки не запускаются. CI отдельно устанавливает официальный Codex 0.166.0 и проверяет нативную команду proxy на каждой ОС; полный обмен реальной сессии с Telegram на macOS/Linux ещё требует проверки.

Данные находятся вне репозитория: `%LOCALAPPDATA%\codex-telegram-relay` на Windows; `$XDG_CONFIG_HOME/codex-telegram-relay` либо `~/.config/codex-telegram-relay` на Linux/macOS. Папка содержит токен, настройки и SQLite-базу с привязками и текстами исходящих сообщений. Доступ ограничивается при настройке. Для отдельной установки можно задать `CODEX_TELEGRAM_RELAY_HOME`.

Временная недоступность одной сессии не отключает остальные. Потеря самого соединения с Codex по-прежнему вызывает переподключение.

Перед созданием топика мост сохраняет попытку в базе. Если Telegram мог создать топик, но ответ потерялся, автоматические повторы останавливаются даже после перезапуска. Бот присылает инструкции: если топик появился, отправить `/bind ID` из него; если не появился — явно повторить создание командой `/repair ID`. Эти команды доступны только владельцу и не запускают команду в Codex.

При явной ошибке «топик не найден» мост создаёт замену для загруженной сессии и переносит недоставленные ответы. Старая история не импортируется; прежние кнопки разрешений отключаются, а ожидающие вопросы подключаются заново. Чтобы удалить топик насовсем, сначала отключи его сессию командой `sessions ignore ID`, затем удали топик в Telegram.

После обрыва мост переподключается. Повторные Telegram updates не выполняют команду дважды. При неопределённом результате записи она **не повторяется автоматически**: сначала проверь терминал. Старые вопросы, полученные до подключения моста, иногда требуют ответа в терминале. Неподдерживаемые или слишком большие approvals также остаются для проверки в терминале.

Это первая версия для разработчика. На настоящем Codex CLI 0.166.0 под Windows проверены подключение, финальный ответ, вопрос, steering и отмена разрешения через второго клиента с Telegram-имитатором. Затем на настоящем боте проверены топики, двусторонние сообщения, форматирование и ответ на нативный вопрос. Сон компьютера и восстановление связи, другие версии Codex и установка на чистой машине ещё требуют проверки. Подробности: [проверки](docs/verification.md), [архитектура и ограничения](docs/architecture.md), [безопасность](SECURITY.md).

Самостоятельный проект, не официальный продукт OpenAI или Telegram. Лицензия MIT.

## Вложения и вопросы

В топик проекта можно отправить фото, скриншот, документ, голосовое, аудио, видео, видеосообщение или анимацию. Файлы скачиваются через официальный Telegram getFile; ссылка с токеном бота не передаётся Codex. Лимит облачного скачивания — 20 МиБ на файл. Приватный кеш находится вне репозитория: до 200 МиБ, хранение семь дней, очистка просроченных файлов при следующем вложении. Альбом приходит отдельными сообщениями, а не одним общим запросом.

JPEG, PNG и WebP передаются как изображения, другие файлы — с локальным путём. Для небольших UTF-8 файлов добавляется ограниченный фрагмент текста. Подпись также передаётся сессии. В ответе на нативный вопрос вложение представлено текстом и путём: для просмотра агенту могут потребоваться его обычные разрешения. Мост не запускает и не распаковывает загруженные файлы.

Звук и видео принимаются как файлы, но эта версия не расшифровывает речь и не извлекает кадры. Для этого нужен отдельный локальный обработчик либо явно разрешённый внешний сервис. Права сессии при чтении и обработке файлов не расширяются.

Вопросы request_user_input_async тоже доставляются с кнопками: Codex 0.166.0 не показывает их через App Server, поэтому мост читает соответствующие записи выбранной сессии. Журнал просматривается порциями по 1 МиБ; сохраняются только записи вопросов/ответов текущего хода, с лимитом отдельной записи 256 КиБ. Большой вывод инструментов не обрезает восстановление вопросов и не вызывает предупреждения только из-за размера журнала. Ответ отправляется в ту же сессию как обычное сообщение пользователя; исходная форма в интерфейсе Codex может остаться открытой. При первом подключении восстанавливаются вопросы последнего хода в пределах семи дней. Для известных незакрытых вопросов граница восстановления сохраняется и после новых ходов/перезапусков, без импорта посторонней старой истории. При неподдерживаемом или секретном вопросе приходит уведомление о необходимости ответа в терминале. При выключенном мосте или потере связи уведомление доставить невозможно.

## Обновление Codex и восстановление пути

Если обновление удалило сохранённый бинарник Codex, открой обычные сессии Codex и перезапусти релей. Он повторно проверит штатные места установки и сохранит новый путь только после успешного подключения и проверки списка сессий общего daemon. Токен, привязка владельца и ID топиков сохраняются. Проверка не скачивает CLI, не запускает отдельный daemon и не обращается к модели. Совместимость за пределами проверенной версии Codex требует отдельной проверки.

Если автоматический поиск не помог, укажи установленный нативный бинарник:

```sh
npm start -- start --codex-bin /absolute/path/to/native/codex
```

На Windows нужен абсолютный путь к codex.exe. Существующий, но некорректный файл не заменяется молча. doctor --codex-bin PATH проверяет указанный путь без изменения конфигурации.

Известные незакрытые host-вопросы сохраняются при новом ходе и переподключении. Граница восстановления расширяется только для этих вопросов; посторонние старые вопросы не импортируются. О превышении размера или количества вопросов приходит уведомление о необходимости терминала. Частичные ответы хранятся приватно до семи дней и восстанавливаются при совпадении стабильных ID и содержания вопросов. При явном отказе Codex ответ можно повторить; принятые или неопределённые отправки автоматически не повторяются.
